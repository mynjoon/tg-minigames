# 공일모바일 플라이휠 — 아마존 모델 적용 (2026-07-27 제정)

베조스의 플라이휠 원리: **성장의 각 요소가 다음 요소를 밀어주는 자기강화 루프.**
바퀴는 처음엔 무겁게 돌지만, 한 바퀴 돌 때마다 다음 바퀴가 가벼워진다.
운영 원칙은 하나 — **매주 가장 느린 바퀴살 하나를 찾아 그것만 민다.**
(SETKORA 플라이휠의 오프라인 매장 버전. 원본: skyrental-toss/tools/FLYWHEEL.md)

## 루프 A — 본체 루프 (상담 경험 → 방문 전환)
1. **투명한 상담 경험** — 예상 범위 공개·매장 확정 원칙 · 중고 등급 기준 공개 · 예약 즉시 응답
2. → **만족 고객의 리뷰·소개** (네이버 플레이스 리뷰가 오프라인 매장의 통화)
3. → **지역 검색 노출 상승** (플레이스 순위 = 리뷰 수·응답·정보 최신성)
4. → **예약·방문 증가** → 개통·매입 매출 증가
5. → **시세·콘텐츠 재투자** (단가표 갱신·신모델 반영이 빠를수록 사이트 신뢰 상승) → 1로 복귀

## 루프 B — 중고 매입 루프 (재고 순환)
중고 매입(공개 등급 기준) → 검수·정비 → 중고 판매 재고 확보 → "중고폰 구매" 상담 접수 →
판매 + 그 고객의 다음 기변 상담 → 다시 매입 → …
- 매입가 신선도가 시동 키: **단가표가 갱신될수록 사이트 계산기의 신뢰가 복리로 쌓인다.**

## 루프 C — 검색·AI 콘텐츠 루프 (온라인 유입 복리)
사이트 콘텐츠(기기·중고 시세·FAQ) → 네이버/구글 색인 + AI 검색 인용(llms.txt) →
검색 유입 → 서치콘솔 쿼리 데이터 → 부족한 콘텐츠 발굴 → 콘텐츠 보강 → …
- 콘텐츠는 감가상각 없는 자산. "마장동 중고폰 매입" 같은 지역 쿼리를 하나씩 점령한다.

## 주간 플라이휠 지표
| 바퀴살 | 지표 | 소스 | 담당 |
|---|---|---|---|
| 경험 | 예약→방문 전환, 상담 응답 속도 | 예약 알림·매장 | 사장님 |
| 리뷰·추천 | 플레이스 신규 리뷰 수·평점 | 네이버 스마트플레이스 | 사장님 |
| 트래픽 | 색인 페이지 수·검색 유입 | 서치어드바이저·서치콘솔 | 사장님(확인)+Claude(개선) |
| 전환 | 주간 예약·중고 상담 접수 수 | 예약 폼·상담 폼 알림 | 사장님 |
| 시세 신선도 | 단가표 기준일 경과일 | 사이트 /used 표기 | 사장님(사진)+Claude(반영) |
| 콘텐츠 | 신모델·FAQ 반영 속도 | 사이트 | Claude |

## 운영 원칙 (아마존식 3계명)
1. **병목 우선** — 모든 바퀴살을 동시에 밀지 않는다. 가장 느린 곳 하나만.
2. **경험이 입력, 매출은 출력** — 출력을 직접 밀지 않는다. 확정가·최저가 과장 금지 가드레일이 플라이휠보다 우선.
3. **Day 1** — 자동화 기본값. 사장님 개입은 ①단가표 사진 ②예약 응답 ③리뷰 관리 세 가지로 최소화.

## 현재 병목 (2026-07-27)
**트래픽(색인)** — 사이트·SEO·AI SEO 세팅은 완료됐으나 네이버·구글 색인이 이제 막 시동.
시동 키: 색인 요청 완료 + **네이버 스마트플레이스에 사이트 연결** + 첫 리뷰 10개.
색인이 잡히는 2주간은 리뷰(루프 A-2)를 미는 것이 가장 효율적.

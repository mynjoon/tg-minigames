# Growth Engine — 공일모바일

전문은 `PLAYBOOK.md`. 시작 전에 반드시 알아야 할 것만 여기 적는다.

## 가장 중요한 규칙: 성장 병목 사슬
유입은 사슬이고 **앞 단계가 0이면 뒤 단계 최적화는 전부 낭비다.**
`① 크롤 → ② 색인 → ③ 노출 → ④ 클릭 → ⑤ 방문 → ⑥ 행동 → ⑦ 접수 → ⑧ 성사`
**가장 앞에서 0에 가까운 단계 하나만 민다.** 추측으로 건너뛰지 말고 숫자를 실제로 뽑아 내려온다.

## 절대 타협 금지 6가지 (각각 실제 사고에서 나옴)
1. 검증에 필터를 걸면 그건 검증이 아니다 — 실패 요청은 확장자 구분 없이 전부 센다
2. 배포 게이트를 통과해야 배포한다 (`node tools/deploy-gate.mjs`)
3. HTML·JS가 뱉는 경로는 루트 절대경로 (상대경로는 depth 2에서 전멸)
4. 모든 페이지는 내부링크 인바운드 ≥1 (사이트맵에만 있으면 색인 안 됨)
5. 지표에 자동화·내부 접속이 섞이면 결론이 뒤집힌다 (`track.js`가 차단 — 일반어 `bot|spider` 금지, CUBOT 오차단)
6. 1회 측정으로 회귀 단정 금지 — 성능·순위·CTR은 3회 중앙값

## 공일모바일 고유 (오프라인 매장)
- **네이버 플레이스·지도가 1순위**, 구글은 보조. 핵심 채널에 쓰기 API가 없다 →
  자동화의 역할은 **발행이 아니라 준비(초안 생성)와 감시(추적·회귀)**. "자동 게시"를 약속하지 마라.
- 노릴 쿼리: 지역+거래의도("마장동 중고폰 매입") · 상담형("번호이동 기변 뭐가 유리") · ⭐외국인+유심
- 피할 쿼리: 기기명 단독, 전국 "성지" 류(과장광고 규제 충돌)
- **전화(`tel:`)가 최대 전환 채널** — `track.js`가 위임 방식으로 자동 집계
- 예약→내점→성사 이탈은 온라인에 안 보인다. 내점·성사는 사장님 회신으로 주간 집계
- 가격은 항상 "예상 범위 + 매장 확정" (KICKOFF/CLAUDE.md 가드레일이 성장보다 우선)

## 이 저장소에 설치된 것
| 파일 | 용도 |
|---|---|
| `tools/site.mjs` | 사이트 상수 단일 소스 (도메인·브랜드·NAP) |
| `track.js` | 측정 계층 — 자동화/내부 제외, 큐 시밍, tel·카톡·지도 클릭, 폼 단계 |
| `analytics-config.js` | GA4 측정 ID 슬롯 (비어 있으면 전송 안 함, 나머지는 정상 동작) |
| `tools/deploy-gate.mjs` | 배포 전 브라우저 검사 — 위반 시 exit 1 |
| `tools/seo-check.mjs` | 라이브 SEO 회귀 감지 (일일) |
| `scripts/google-api.mjs` | GA4·GSC 조회 (서비스계정 JSON 필요) |
| `docs/FLYWHEEL.md` | 주간 플라이휠 지표·병목 판단 |

## 운영
- **일일**: `seo-check` + 예약 API 생존. 통과는 조용히, 실패만 보고.
- **주간(월)**: GSC 색인 추이 → 쿼리 마이닝 → 링크 감사 → 채널 성과(UTM) → **병목 1개 지목**
- **월간**: 콘텐츠 1편 실질 갱신(날짜만 갱신 금지) · 데이터 감사 · PSI 3회 중앙값
- 신규 도메인 첫 4주는 **색인 대기 구간** — 순위·유입으로 판단하지 말고 GSC 색인 추이만 본다
